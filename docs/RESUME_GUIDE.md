# SolarAI-X简历与面试指南

## 推荐项目名称

**SolarAI-X——基于MCP与RAG的太阳能领域智能分析Agent**

## 简历三条描述

- 基于DeepSeek与MCP构建太阳能领域智能分析Agent，将知识检索、硅电池参数仿真、钙钛矿老化/参数/带隙预测及曲线绘制封装为9个领域工具，实现模型动态发现工具、生成参数、执行调用并基于工具结果完成回答。
- 构建基于BGE Embedding的本地RAG流程，完成领域文档向量化、来源映射和Top-N相似内容检索；通过FastAPI与SSE实现大模型内容、推理过程及工具图像结果的流式传输。
- 使用Gradio实现AI对话、硅电池预测、钙钛矿老化、器件参数与带隙预测五个功能页面；引入模型能力健康检查和降级启动机制，使外部AutoGluon模型未配置时其他模块仍可独立运行。

## 技术栈

`Python / DeepSeek API / MCP / Tool Calling / RAG / BGE / FastAPI / Gradio / PyTorch / AutoGluon / SSE / pytest`

## 30秒介绍

SolarAI-X是一个面向太阳能和钙钛矿领域的智能分析Agent。它不是只让大模型回答问题，而是通过MCP向DeepSeek提供9个领域工具，包括知识检索、太阳能电池仿真、钙钛矿老化和带隙预测。模型根据用户问题选择工具、生成参数，Python执行后把数值和图表返回模型，再由模型生成最终解释。系统使用FastAPI提供流式接口，并用Gradio完成可视化展示。

## 面试时必须区分的内容

- 如果AutoGluon模型不是你亲自训练的，应说“集成并封装模型”，不要说“独立训练模型”；
- RAG使用BGE Embedding和本地PKL向量，不要声称使用了向量数据库；
- 对话历史当前是内存存储，不要声称已经实现数据库长期会话；
- 带隙模型中的指标来自现有模型结果，不能表述为线上业务准确率；
- MCP负责工具发现和执行协议，DeepSeek负责工具选择和自然语言回答。

## 高频追问

### 为什么使用MCP，而不是在FastAPI里直接调用函数？

MCP把工具名称、描述、参数Schema和执行接口标准化。领域工具可以独立运行，也可以被不同模型客户端复用。FastAPI只负责会话、流式输出和协调，不需要硬编码每一个工具的调用方式。

### RAG的数据流是什么？

领域文档先通过BGE生成向量，同时保存文本与来源文件映射。用户提问时生成查询向量，计算相似度并返回Top-N片段；片段作为工具结果放回对话上下文，再由DeepSeek生成最终回答。

### 模型目录缺失为什么服务还能启动？

维护版将模型加载从“强制启动条件”改成了“独立能力状态”。启动时记录各模型组是否加载成功，健康接口返回具体状态；只有调用缺失模型对应的功能时才返回503，因此聊天、带隙预测等其他模块不受影响。

### 项目最大的不足是什么？

当前对话只保存在内存中，RAG还是本地文件向量，AutoGluon模型制品需要单独配置，自动测试尚未完整模拟LLM工具调用。下一步会增加SQLite会话、向量数据库、Fake LLM集成测试和Docker Compose。
