# SolarAI-X 带隙模型审查与修复 v4

本轮已将 API、MCP 与页面的带隙能力统一，并修复未验证科学模型仍返回预测值的问题。两套依赖环境分别通过全部 138 项测试，失败、错误与跳过均为 0；pip check 均无依赖冲突。本轮没有新增 SolarAI-X 真实模型调用。

## 发现与复现

三个历史多项式实现按有序乘积展开特征，会重复出现 x*y 与 y*x，再按系数数量截断，不能保证与训练时的单项式顺序一致。项目缺少训练脚本、训练数据、特征变换与可重现验证记录，用户已确认没有另外保存这些资料。将展开改为常见的标准顺序后，原系数仍能输出异常值，因此没有将推测的顺序当作修复后的可信模型。

以下是修复前函数的本地数值复现，均为合法比例输入：

| 历史模型 | 参数 | 原函数结果 eV |
|---|---|---:|
| CsMAFAPbIBr | Cs=0.1, FA=0.7, I=0.8 | 16.512917 |
| MAFA | MA=0.3, I=0.8 | -60.921075 |
| CsFA | Cs=0.3, I=0.8 | -5465.618635 |

这些值用于说明实现和模型适用性存在问题，不是材料实验数据或新的预测精度证据。

## 当前行为

- MAPbIBr 使用原项目公式 `1.565 + 0.15 * Br_percentage`，保持 Br=0、0.5、1 时的计算结果 1.565、1.640、1.715 eV。API 与 MCP 共同返回 formula_only 与 empirical_accuracy_verified=false，页面明确说明其为公式演示。
- CsMAFAPbIBr、MAFA、CsFA 暂不注册为可用预测模型。API 返回 503 和具体原因，MCP 返回能被现有工具运行时识别的错误，页面不再提供这三类可计算选项。
- 历史系数保存在 api/bandgap_legacy_coefficients.json，只用于追溯，运行中的预测函数不加载这些系数。原先硬编码的模型精度指标不再作为预测结果返回。
- 所有入口共享 BandgapParameters：检查类型、必填参数、有限数值、比例范围，并拒绝布尔值和字符串冒充数值；Cs 与 FA 的比例之和不能超过 1。
- 健康接口新增 bandgap 能力表，GET /api/perovskite/bandgap-models 返回相同状态。页面请求带隙 API 的超时设为 30 秒，并展示输入错误和模型不可用的具体原因。

## 验证与恢复条件

22 项新增回归覆盖公式边界、API/MCP 一致性、无效输入、组分约束、未验证模型的 HTTP/MCP 错误和能力状态一致性。完整回归还包含实际本地离线工具演示和 Gradio 页面构建。两套环境各 138 项通过。

恢复三个多项式模型前，需要提供可核验的训练数据、输入字段与单位、特征变换和顺序、模型文件、适用组分范围，以及独立验证集上的误差记录。当前代码未重新训练模型，也不能据此声称材料预测精度提升。
