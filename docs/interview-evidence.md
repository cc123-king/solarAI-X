## 如何复现

PowerShell 执行：

```powershell
Set-Location 'C:\Users\dcc\Documents\ChatGPT\agent\solarAI-X'
.\.venv\Scripts\python.exe -B scripts/collect_interview_evidence.py
```

脚本依次跑完整 pytest、pip check、检索评测、本地工具演示。打印的 `outputs/evidence/evidence-...` 目录是本次结果，不要拿旧报告冒充修改后验证。

`manifest.json` 记录代码 SHA256、环境版本和退出码；`pytest.log` 保留真实测试数量和警告；检索目录保留每个问题返回的来源、得分、原文与是否包含标注锚点。测试用独立临时目录，避免系统 Temp 权限干扰。

不会调用收费模型、修改 API Key 或知识库；不下载 BGE。默认关键词后端，`HF_HUB_OFFLINE` 等也在证据收集子进程中启用。不要加载陌生来源的 pickle。

## 三分钟展示顺序

1. 展示一键证据的 `summary.md` 和测试结果，说明本次验证的代码版本。
2. 打开离线演示的 `tool-catalog.json`，指出工具名称、描述和参数 Schema。
3. 展示 `search-and-bandgap.json`：第一轮检索真实手册，第二轮计算 `MAPbIBr` 的 Br 比例0.5，得到1.64 eV，结果进入下一轮模型消息。
4. 展示越界比例或未知工具场景：请求被拒绝，调用次数为0；轮次场景则最多执行2轮。
5. 打开检索评测报告，解释选参数只使用开发组，测试组保持不变；展示一条失败题，不回避跨语言与无答案检索问题。

这套演示无需 Key，模型请求是脚本预设、工具是真实本地函数。不要说“演示证明模型自己准确选了工具”。如需展示真实自主调用，再从项目根目录启动 MCP、API 和 Gradio，使用自己的 Key 人工验收；健康检查的 configured 只说明配置存在，不说明请求已成功。

## 检索指标怎样理解

- 来源命中：预期文件是否出现在前k个保留结果。
- 证据命中：结果不只来自正确文件，还包含事先标注的原文锚点。
- 证据MRR：正确证据排得越靠前，分数越高。
- 无答案空检索：资料不存在时是否不返回片段。这不是模型拒答率。

参数搜索只有开发组：k为1/3/5，阈值为0.05/0.15/0.30/0.50，均衡考虑证据命中和无答案空检索。冻结后才执行测试组。

评测阈值不会自动同步给网页：现有工具的 `min_similarity` 控制语义候选阈值，关键词后端仍使用 `RAG_LEXICAL_MIN_SCORE`。两种分数不是同一种相似度，不能把评测选出的参数误当成已经上线，也不要把关键词得分称为向量相似度。

旧库来源16份、片段2514个。600字符＋80重叠仅用于内存对照，不覆盖旧库。初次实测中，重切片的证据命中反而低于原片段，因此没有根据“切得小通常更好”直接改线上资产。中文问英文手册的问题在关键词模式下也较弱，少量领域别名不等于真正跨语言语义能力。

报告另外记录工具实际输出窗口的证据命中，防止“召回完整片段含答案，但给模型的摘要截掉答案”被完整片段指标掩盖。以上都不评价生成回答质量、科学预测精度或真实模型工具决策。

## 两个可以讲的开发问题

### 问题一：能解析成JSON，不代表工具参数有效

现象：模型返回 `{"Br_percentage": 2}` 是合法JSON，但比例不应超过1。只调用 `json.loads`，不足以防止错误参数进入工具。

解决：从 MCP 工具目录取得 JSON Schema，执行前验证类型、必填字段和数值边界；把参数错误作为工具消息返回下一轮模型，而不是直接执行。拒绝未注册工具，并限制轮次。

验证：非法JSON、错误类型、缺必填、比例越界和未知工具都有自动测试；越界比例的真实Schema演示确认工具没有执行。

面试回答示例：“我把模型输出当作不可信输入，不是它生成了合法JSON就相信它。参数先过工具Schema，再检查工具权限，最后才进入执行层。模型可以提出调用，但不能绕过后端约束。”

### 问题二：检索找到依据了，模型仍然看不到

现象：旧知识库片段较长，工具固定只截前500字。相关片段虽然被检索命中，后半段的关键语句可能没有进入模型上下文。工具循环的上下文标志还可能在实际结果到达前被设为已发送。

解决：短片段保留完整原文，长片段按查询词选择有界的连续原文窗口，保留来源及是否截断；只有有工具结果时才标记已发送，每轮完成后重置标志。评测分别记录完整片段和实际窗口的证据命中。

验证：构造答案位于500字之后的测试；真实手册检索检查 `EXTRACT NAME="FF"` 到达后续模型消息；多轮上下文数量按1、2更新。

面试回答示例：“我不只检查检索函数返回了什么，还检查经过工具封装后，真正送给模型的内容。否则指标看起来命中，但模型没有看到证据，仍会回答错。”

以上是这轮工程维护中实际发现并修复的问题。你需要读懂对应代码后，按真实参与程度讲，不要描述成独立从零完成全部架构。
