# 多轮上下文与工具结果压缩

已知会话优先使用服务端保存的历史，再加入本次用户消息；客户端提供的额外system或tool消息不会升级为可信指令或真实工具结果。每轮模型调用前按字符预算选择近期完整对话轮次，保留系统指令、当前完整问题、当前任务的工具调用与结果配对。

## 配置

`LLM_MAX_CONTEXT_CHARS=64000`为请求消息与工具定义JSON的字符预算，`LLM_HISTORY_TURNS=8`为最多保留的历史轮次。预算不是Tokenizer计算的Token数量，也不等同于模型上下文窗口规格。

超过预算时先删除完整旧轮次。当前问题与执行轨迹仍无法容纳时，明确返回错误，不截断用户约束或拆散工具调用关系。开启任务追踪时保存context_budget事件，记录原始/实际字符量及裁剪轮数。

## 数组压缩和数值引用

大数组和长文本在模型上下文中转为标注了_context_excerpt的结构化预览，包含长度和可用的result_id、path。完整原始结果仍由本任务ExecutionEvidence持有，绘图可通过result_refs读取完整数值。

例如预览给出`{"result_id":"compute-1","path":["curve","y"]}`，绘图引用可为`{"target":"y_data","result_id":"compute-1","path":["curve","y"]}`。不能把preview当完整曲线，也不能把引用对象直接放入y_data。产物校验和跨任务引用限制保持。

工具结果压缩为确定性结构摘录，不使用额外模型调用生成摘要。语义信息可能因裁剪而不在当前上下文中；服务不会声称保留了完整语义。

## 离线演示

执行`python scripts/demo_context_budget.py`，使用合成历史和1000个示例数值，展示旧轮次裁剪、工具数组预览与完整数值回填。它不调用LLM，不是1000条真实Agent任务评测。

新增测试覆盖服务端历史恢复、旧轮次完整删除、工具定义占用预算、当前任务溢出拦截、工具调用配对、数值不变及跨任务引用拒绝。现有40任务的真实模型成绩保持历史口径，本轮没有新的模型成功率结论。
